## 1. 项目概述

### 1.1 背景与痛点

企业在系统数量增多后普遍面临：

1. **业务路线不透明**：一条业务从开始到结束，实际走哪些系统、库、部门？靠人脑记忆，问一个人一个说法。
2. **多条路线说不清**：同一起终点往往有多条可走路线（默认/备选/特殊场景），没人画出来。
3. **出问题不知道卡在哪**：流程走到某节点停了、没走到终点，是哪个环节？人工逐环节排查很慢。
4. **环节耗时不可见**：每环节花多久、哪条路线最慢、瓶颈在哪，没有数据。
5. **数据准确性难核实**：某个环节数据对不上，涉及哪些数据流、该查哪个库表，缺少线索。
6. **知识断层与变更风险**：核心流程知识在人脑里，人走即断；改动某个环节影响哪些路线，说不清。

### 1.2 产品愿景（血管网类比）

> **错综复杂的血管网 = 关系网；血液流向 = 数据/业务流向；血栓 = 出问题的环节；顺藤摸瓜 = 从问题环节逆血流找源头、顺血流看影响。**

把系统、数据库、部门、业务环节画成一张**像血管系统一样错综复杂但脉络清晰**的关系网，给同一起终点提供**多条路线**，并在系统出问题时**顺着关系网把根因和影响面摸出来**。

### 1.3 核心定位（三大核心）

| 核心 | 含义 | 一句话 |
| --- | --- | --- |
| **陈列** | 节点关系网的展示 | 把错综复杂的血管网画清楚 |
| **择路** | 多条路线的选择 | 同一起终点给多条路线、可对比 |
| **摸瓜** | 顺藤摸瓜式问题排查 | 从问题环节找到源头和影响面 |

其余一切能力（检测点、实例、卡点、耗时、告警、工单、看板）都是**服务于"摸瓜"的信号源与工具**。

## 3. 核心能力需求

### 3.1 核心一 · 陈列：节点关系网的展示

- 4 类混合站点作节点：系统/子系统、数据库/表、部门/岗位、业务动作/事件（制造场景预留设备/工序/工位）
- 有向连线表达流向，支持**分岔与汇合**（血管主干 + 分支）
- 力导向自动布局、节点拖拽、缩放/平移/全屏
- 点击节点 → 详情（属性、上下游、所在路线）
- 一键高亮某节点**全部上下游**；搜索 / 类型过滤 / 按流程切换
- 复杂时**折叠 / 展开**子网

### 3.2 核心二 · 择路：多条路线的选择

- 流程（起点→终点）下，从路网定义多条**完整路线**，标优先级：**默认 / 推荐 / 备选**
- **路线视图**：一条路线按站点顺序串联（一条地铁线）
- **路线对比**：并排对比站点构成、长度，高亮共享/差异站点
- **任意两点路径查询**：A→B 有哪几条走法

### 3.3 核心三 · 摸瓜：顺藤摸瓜式问题排查 ⭐

```
▸ 点击问题站点 → 图上高亮它所有关联（上下游全亮）
▸ 向上摸藤（溯源）：数据/业务从哪来？上游站点带检测点状态，可疑者标红
▸ 向下看瓜（影响）：影响哪些下游、哪些路线、哪些业务单号
▸ 多路线视角：这个站在哪几条路线上，各影响多大
▸ 排查建议：按"最可疑→最无关"排序，引导一步步定位根因
```

- 排查轨迹留痕、可回退；实例排查全程用**业务别名**标注便于记忆
- 配套**业务单号全局反查**：输入单号/显示名/别名 → 直接定位实例当前卡点

## 5. 模块划分与功能需求

### 5.1 模块总览

| 模块 | 职责 |
| --- | --- |
| 数据接入模块 | 外部数据图来源统一接入（连接器可插拔） |
| 建模模块 | 流程/站点/路网/路线编辑维护 + 版本留存 |
| 监控排查模块 | 实例追踪、卡点定位、检测点、顺藤摸瓜 |
| 分析模块 | 路线对比、路径查询、影响面、溯源、耗时 |
| 告警+工单模块 | 等级驱动预警/干预、通知、工单跟踪 |
| 配置版本模块 | 全配置版本留存/对比/回滚/审批 |
| 开放 API 模块 | 对外查询/上报/触发接口 |
| 看板报表模块 | 状态看板、管理报表、大屏 |

### 5.2 数据接入模块（独立模块）

- **连接器可插拔**：数据库（MySQL/Oracle/PG 采集库表→站点候选）、Excel/CSV 导入、CMDB/资产 API、日志解析、IoT/设备（远期）
- 流程：创建连接 → 测试 → 采集任务（手动/定时）→ 生成候选 → 映射确认 → 入库 → 采集日志 + 变更检测（新库/新表提醒）
- 映射规则可配置：如"外部表名 = 站点名""库名 = 归属系统"

### 5.3 监控排查模块（核心）

- 检测点：默认（按站点类型自动生成：库→数据量/新鲜度/延迟；系统→状态/心跳；动作→完成/耗时）+ 自定义（阈值 / SQL / 脚本）
- 实例追踪：一次真实运行 = 实例，记录每站到达/离开/耗时/状态
- 卡点定位、耗时分析、数据核实、顺藤摸瓜排查、业务单号反查

### 5.4 告警+工单模块

- 等级驱动预警/干预（见 6.3）；通知渠道：站内 + 邮件（钉钉/企微远期）
- 工单：告警→工单，指派责任人、跟踪 OPEN/PROCESSING/RESOLVED

### 5.5 配置版本模块

- 对象：流程/站点/路线/路网边/检测点/接入配置
- 留存最近 N 版 + 改动记录（谁/何时/改了什么/diff）+ 对比 + 回滚
- 高等级变更可配置审批（DRAFT/PENDING_APPROVAL/PUBLISHED/ROLLED_BACK）

### 5.6 开放 API 模块

- 对外 REST API：上报实例、查询流程/站点/路线、触发检测、获取告警
- 鉴权：API Token；用途：外部系统集成、实例自动采集通道

## 6. 核心概念与数据模型

### 6.1 领域模型

```
场景 Scene（数据流 / 业务流程 / 制造流程·远期）
 └─ 流程 Process（起点→终点，带等级）
     └─ 路网：站点 Node（带等级）+ 有向边
         └─ 路线 Route（优先级 + 等级）
             └─ 实例 Instance（业务单号 + 业务别名）
                 └─ 每站到达/离开/耗时/状态
                      └─ 检测点 Checkpoint（带等级）→ 检测结果 → 告警 → 工单
```

### 6.2 命名与别名体系

- 所有对象（关系网/流程/路线/实例/站点/检测点/告警）支持 **1 个主显示名 + 多个别名**
- 界面默认显示主名，详情/悬停显示单号；全局搜索**单号 + 显示名 + 别名通吃**
- 通用 `alias` 表 + `instance.biz_name`；支持批量导入别名

### 6.3 版本与等级体系

等级打在流程/站点/路线/检测点上：

| 等级 | 版本管控 | 预警策略 | 干预策略（三动作组合） |
| --- | --- | --- | --- |
| L1 核心 | 变更需审批 | 异常立即告警+升级 | **系统自动动作 + 生成工单 + 通知负责人** |
| L2 重要 | 变更需审批（可选） | 失败/超时告警 | 生成工单 + 通知负责人 |
| L3 普通 | 正常留存 | 汇总提醒 | 通知 / 记录 |
| L4 一般 | 正常留存 | 仅记录 | 仅记录 |

- 系统自动动作：自动重试、暂停流程（**总开关 + 单节点开关 + 可回滚**，防误伤）
- 干预边界：自动动作默认**只在平台内**生效，不回写业务系统（见 9 节）

### 6.4 数据模型

完整 DDL 见**附录 A**。核心表：`node` / `relation` / `process` / `route`+`route_node` / `checkpoint`+`check_result` / `instance`+`instance_node` / `alert` / `ticket` / `config_version` / `connector` / `import_job` / `import_log` / `alias`。

## 7. 技术方案（✅ 已确认）

### 7.1 架构总览

```
┌────────────── 前端 Web（Vue 3 + TS + 图引擎）──────────────┐
│  关系网画布（G6 2D → 3d-force-graph 3D）│ 排查/看板/大屏     │
└─────────────────────┬───────────────────────────────────────┘
                      │ REST / WebSocket
┌─────────────────────▼───────────────────────────────────────┐
│        后端 Spring Boot 3（Java 17，模块化）                  │
│  建模│分析│监控引擎│检测引擎│告警│工单│版本│开放API│数据接入   │
│  定时任务（@Scheduled：检测点轮询/采集）                      │
└─────────────────────┬───────────────────────────────────────┘
                      │
        MySQL 8（主库）     [可选] Redis     [远期] Neo4j
```

### 7.2 前端技术栈（✅ 已确认）

| 用途 | 选型 |
| --- | --- |
| 框架 | **Vue 3 + TypeScript** |
| 图可视化 2D | **AntV G6 5.x**（编辑/布局/交互） |
| 图可视化 3D | **3d-force-graph**（Three.js，粒子流向动画） |
| 状态/路由 | Pinia + Vue Router |
| UI 组件库 | Element Plus / Ant Design Vue |
| 看板图表 | ECharts |
| 构建/部署 | Vite + nginx |

### 7.3 后端技术栈（✅ 已确认）

| 用途 | 选型 |
| --- | --- |
| 框架 | **Spring Boot 3.x + Java 17** |
| ORM | **MyBatis-Plus** |
| 图分析 | 内存图自研（邻接表 + BFS/DFS/环检测），预留 Neo4j 接口 |
| 定时任务 | Spring @Scheduled（起步够用，复杂再上 Quartz） |
| 鉴权 | Spring Security + JWT（或 Sa-Token） |
| 加密 | AES（数据源密码） |
| API 文档 | springdoc-openapi (Swagger) |
| 校验/日志 | Hibernate Validator + SLF4J/Logback |

### 7.4 存储

MySQL 8 主库（建模+监控+版本+告警+工单元数据）；Redis 可选（缓存/会话）；Neo4j 远期（图查询规模化，按几百站点预留）。

### 7.5 部署运维

Docker Compose 一键部署（nginx + 后端 + MySQL）；Flyway 数据库迁移；mysqldump 定时备份 + 恢复演练；告警值班（站内+邮件，可配置轮值）；操作审计日志。

### 7.6 安全

HTTPS；数据源密码 AES 加密存储、不明文回显；生产库只读最小权限；敏感系统（财务/支付/L1）访问审计；多用户 RBAC。

### 7.7 测试

后端 JUnit5 + Mockito；前端 Vitest；可选 Playwright E2E。

### 7.8 技术取舍说明

1. **G6 打底 + 3d-force-graph 做 3D**：2D 编辑靠 G6，3D 展示/粒子动画靠 3d-force-graph，数据模型统一 nodes+links。
2. **先内存图、不急着 Neo4j**：站点量级不大时，内存 BFS/DFS 完全够，省一套图数据库运维，预留升级路径。
3. **轮询而非消息队列**：已确认准实时轮询，Spring 定时任务即可，不上 Kafka，降低起步复杂度。

## 9. 数据安全与权限边界

- **生产库只读最小权限**：平台永不写入业务系统
- 数据源密码 AES 加密存储，界面不明文回显
- **干预边界**：自动暂停/重试默认只在平台内生效（标记实例状态）；如需回写业务系统，通过业务系统受控 API 单独授权（远期）
- 敏感系统访问审计 + 多用户 RBAC（按流程/关系网授权）

## 10. 实例采集落地约定（M2 前提）

三种机制**结合**，先易后难：

1. **数据特征推断**（M2 先用，无需改造）：轮询业务库关键表，按可配置规则推断环节状态。例：「订单表有记录且 state=已支付 → 已到达支付环节」。
2. **人工标记**（M2 并用）：人工更新实例进度，作补充与兜底。
3. **进度上报表**（二期升级）：业务系统每过一环节向平台约定的进度表/API 写记录。最准，但要业务埋点。

## 13. 落地潜在问题与风险

| # | 风险/问题 | 影响 | 应对措施 |
| --- | --- | --- | --- |
| 1 | **业务系统不配合/采集不到数据** | M2 监控空转 | 先用特征推断+人工标记起步；尽早谈业务方，约定进度上报表 |
| 2 | **图维护失真（没人更新）** | 平台价值归零 | 责任人机制 + 定期校核提醒 + 导入初始数据降低录入成本 |
| 3 | **SLA/阈值设置不合理 → 误报失控** | 失去信任 | 上线设校准期，阈值可调、可静默；按 L1/L2 分级收敛 |
| 4 | **站点规模低估 → 性能瓶颈** | 卡顿 | 按 1000 站点设计，布局异步/分片；预留 Neo4j |
| 5 | **敏感系统合规** | 财务/支付数据泄露风险 | 只读最小权限、访问审计、RBAC 隔离 |
| 6 | **多系统数据定义不一致** | 数据核对困难 | 数据核实保留原始值 + 对比；逐步沉淀口径字典 |
| 7 | **自动干预误操作** | 影响生产 | 自动动作总开关 + 单节点开关 + 审批 + 可回滚；默认平台内生效 |
| 8 | **试点选择不当** | 验证不了价值 | 选高频、可见、可验收的核心流程做试点 |
| 9 | **历史数据膨胀** | 库变大、查询慢 | 180 天归档策略；报表走聚合表 |
| 10 | **团队技能缺口** | 开发慢 | 技术栈选型已倾向主流（Vue/Spring/G6 中文文档全），预留学习缓冲 |
| 11 | **需求蔓延** | 核心做不扎实 | 3D/制造/一体化明确后置；按里程碑验收把关 |
| 12 | **与现有监控/CMDB 重复** | 重复建设 | 定位差异化：平台重在「跨系统流程关联 + 排查」，可对接而非替代 |

## 14. 决策清单

### 14.1 已确认决策（13 项）

1. 路线为**分支网状**（分岔/汇合，可从路网拎出完整路线）
2. 站点为 **4 类混合**（系统/库表/部门岗位/业务动作）
3. 路线需**优先级 + 对比 + 展示**
4. 需要**检测点 + 排查**能力
5. 核心 = **陈列 + 择路 + 摸瓜**
6. **独立数据接入模块**（连接器可插拔）
7. **配置版本 + 等级细分**（L1~L4）
8. **等级驱动预警/干预**
9. **干预 = 通知到人 + 生成工单 + 系统自动动作**（三动作组合）
10. **监控时效 = 准实时轮询**（分钟级）
11. **实例数据 = 自动（库轮询/定时采集）+ 人工标记结合**
12. **命名与别名体系**（主显示名 + 多别名，全局搜索通吃）
13. **工程与验收补充**：NFR、实例采集约定、安全边界、成功指标、部署运维、图质量、移动端远期

## 0. 核心定位（一句话）

> **错综复杂的血管网 = 关系网；血液流向 = 数据/业务流向；血栓 = 出问题的环节；顺藤摸瓜 = 从问题环节逆血流找源头、顺血流看影响。**

把系统、数据库、部门、业务环节画成一张**像血管系统一样错综复杂但脉络清晰**的关系网，给同一起终点提供**多条路线**，并在系统出问题时**顺着关系网把根因和影响面摸出来**。

## 1. 三大核心能力（主线）

### 核心一 · 陈列：节点关系网的展示
分岔/汇合、力导向布局、拖拽、上下游一键高亮、搜索过滤、折叠展开、按流程切换。

### 核心二 · 择路：多条路线的选择
路线定义 + 优先级（默认/推荐/备选）+ 路线视图 + 路线对比 + 任意两点路径查询。

### 核心三 · 摸瓜：顺藤摸瓜式问题排查 ⭐
```
▸ 点击问题站点 → 图上高亮它所有关联（上下游全亮）
▸ 向上摸藤（溯源）：数据/业务从哪来？上游站点带检测点状态，可疑者标红
▸ 向下看瓜（影响）：影响哪些下游、哪些路线、哪些业务单号
▸ 多路线视角：这个站在哪几条路线上，各影响多大
▸ 排查建议：按"最可疑→最无关"排序，引导一步步定位根因
```

## 4. 数据接入模块（⭐ 你要的独立模块，重点展开）

**入口独立**：前端"数据接入"菜单 + 后端独立模块 + 独立表。

**连接器（Connector）——可插拔设计：**

| 连接器类型 | 能做什么 | 阶段 |
| --- | --- | --- |
| 数据库连接器 | 连 MySQL/Oracle/PG…，采集库/表 → 生成"站点候选" | M1 |
| 文件导入器 | Excel/CSV 批量导入节点/路线 | M1 |
| CMDB/资产 API 连接器 | 对接系统清单/资产清单 | M2 |
| 日志解析器 | 从日志解析真实流向（自动血缘前置） | 远期 |
| IoT/设备连接器 | 制造场景设备采集 | 远期 |

**核心流程：**
```
创建连接 → 测试连接 → 采集任务（手动/定时） → 生成站点候选
        → 映射确认（外部数据 ↔ 平台站点类型） → 入库
        → 采集日志 + 变更检测（新库/新表提醒）
```

**映射规则可配置**：如"外部表名 = 站点名""库名 = 归属系统"，一次配置、重复使用。

## 5. 版本管理与等级体系（⭐ 你要的版本留存 + 等级细分）

### 5.1 配置版本留存
- **对象**：流程 / 站点 / 路线 / 路网边 / 检测点 / 接入配置
- 每次改动生成新版本，留存**最近 N 版**（如 20 版）
- 改动记录：**谁 / 何时 / 改了什么 / 前后 diff**
- 支持**版本对比 + 回滚**（回滚同样留档）

### 5.2 等级（Level）细分
等级打在：**流程 / 站点 / 路线 / 检测点** 上：

| 等级 | 含义 | 版本管控 | 预警策略 | 干预策略 |
| --- | --- | --- | --- | --- |
| L1 核心 | 核心链路 | 变更需审批 | 异常立即告警 | 自动干预 |
| L2 重要 | 重要链路 | 变更需审批（可选） | 失败/超时告警 | 通知负责人 |
| L3 普通 | 普通链路 | 正常留存 | 汇总提醒 | 记录待处理 |
| L4 一般 | 边缘链路 | 正常留存 | 仅记录 | 仅记录 |

- 等级可配置（不写死），支持"L1 站点图上置顶/高亮"
- 等级本身也是配置，纳入版本管理
- ⭐ **等级是"管理抓手"**：核心链路严格管控、边缘链路宽松，避免监控噪音

### 5.3 等级 → 预警/干预决策流（✅ 已确认：干预 = 通知到人 + 生成工单 + 系统自动动作，三动作组合）

```
检测点结果异常 → 取节点等级 → 预警策略（是否告警/升级）
                            → 干预策略（三种动作按等级组合）
```

| 等级 | 预警策略 | 干预策略（三动作组合） |
| --- | --- | --- |
| L1 核心 | 异常立即告警 + 升级 | **系统自动动作 + 生成工单 + 通知负责人** |
| L2 重要 | 失败/超时告警 | 生成工单 + 通知负责人 |
| L3 普通 | 汇总提醒 | 通知负责人 / 记录 |
| L4 一般 | 仅记录 | 仅记录 |

**系统自动动作**（预设且可配，防误伤）：
- 自动重试：对失败环节按次数/间隔自动重试
- 暂停流程：对高风险异常自动暂停，防止错误继续传播
- 每个自动动作都有 **总开关 + 单节点开关 + 可回滚**，避免误操作

## 6. 核心概念（领域模型）

```
场景 Scene（数据流 / 业务流程 / 制造流程·远期）
 └─ 流程 Process（起点→终点，带等级）
     └─ 路网：站点 Node（带等级）+ 有向边

                      └─ 检测点 Checkpoint（带等级）→ 检测结果 → 告警
```

## 7. 交互与界面方向

**界面总原则 · 命名与别名体系（⭐ v0.7）**

「全是单号记不住」→ 平台里每个看得见的对象都能取**人话名字**，单号只做底层标识：

| 对象 | 显示名（主别名） | 底层标识 | 例子 |
| --- | --- | --- | --- |
| 关系网/视图 | 可读名 | 编号 | 交易链路网 |
| 流程 | 可读名 | 流程编码 | 付款流程 |
| 路线 | 可读名 + 优先级 | 路线编码 | 标准结算路线（默认） |
| 实例 | 业务别名 | 业务单号 | Q2 对账单 ↔ BZ-2026-0715-003 |
| 站点 | 显示名 + 简称 | 编码 | 订单中心 ↔ ORD-C |
| 检测点/告警 | 可读名 | 编码 | 订单库新鲜度检查 |

能力：
1. 每个对象：**1 个主显示名 + 多个别名**（中文 / 英文 / 简称 / 历史名）
2. 界面默认显示主名，详情 / 悬停显示单号
3. **全局搜索 = 单号 + 显示名 + 别名 通吃**（输 "Q2 对账" 或 "BZ-2026" 都命中）
4. 排查实例全程用业务别名标注，便于记忆
5. 支持批量导入别名

**主界面（路网视图 + 状态叠加）：**
```
┌──────────┬──────────────────────────────┬────────────┐
│ 流程列表   │      关系网画布（核心区域）      │  站点详情   │
│ 实例列表   │   站点带状态色/等级角标          │ 属性/检测点 │
│ 搜索框    │   拖拽连线 / 分岔 / 汇合        │ 上下游/耗时 │
│ 类型过滤   │   路线高亮 / 卡点标红 / L1置顶   │ 数据核实   │
└──────────┴──────────────────────────────┴────────────┘
```

- **全局搜索**（⭐）：支持输入**业务单号 / 显示名 / 别名** → 直接定位对应的实例、流程、路线，显示当前卡在哪个站点、检测点状态
- **排查模式**：问题站为中心，上游/下游分色高亮，左面板可疑排序 + 排查轨迹 + 回退
- **数据接入页**：连接器列表、采集任务、采集日志、站点候选确认
- **版本页**：配置版本列表、对比、回滚、审批

### 技术选型与决策点

| 项 | 推荐 | 说明 |
| --- | --- | --- |
| 图引擎 | G6 5.x（2D）→ 3d-force-graph（3D） | 2D 编辑好、3D 效果强 |

### 8.1 非功能需求（NFR）基线

| 维度 | 目标 |
| --- | --- |
| 性能 | 1000 站点级图：初始布局 ≤ 3s，缩放/拖拽无卡顿；页面加载 ≤ 2s |
| 可用性 | 内网部署，目标 99.5%；单机起步，可水平扩展 |
| 并发 | 在线 20~50 用户，操作类接口 p95 < 500ms |
| 安全 | HTTPS、数据源密码 AES 加密存储、敏感字段脱敏 |
| 兼容 | Chrome / Edge 最新两个大版本 |
| 数据保留 | 实例/检测结果定期归档（如 180 天后），防库无限膨胀 |

### 8.2 实例采集落地约定（⭐ M2 前提）

三种机制**结合**，先易后难：

1. **数据特征推断**（无需业务系统改造，M2 先用）：平台轮询业务库关键表，按可配置规则推断环节状态。例：「订单表有记录且 state=已支付 → 已到达支付环节」。
2. **人工标记**（M2 并用）：人工在平台手动更新实例进度，作为补充与兜底。
3. **进度上报表**（后置，需业务配合）：业务系统每过一个环节，向平台约定的进度表/API 写一条记录（实例号/环节/时间/状态）。最准确，但要业务系统埋点。

> 结论：M2 先用「特征推断 + 人工标记」跑起来，进度上报表作为二期升级路径。

### 8.3 数据安全与权限边界

- **生产库只读最小权限**：平台连接业务库一律只读 + 最小权限账号，永不写入业务系统
- 数据源密码 AES 加密存储，界面不明文回显
- **干预边界**：平台的「自动暂停/重试」默认只在**平台内**生效（标记实例状态），不直接回写业务系统；如需回写，通过业务系统受控 API，单独配置授权（远期）
- 敏感系统（财务/支付/L1）访问审计：记录谁在何时查看了什么
- 多用户 RBAC：按流程/关系网授权，不同角色不同权限

## 9. 数据模型（增量：v0.5 新增表/字段）

- **等级**：`node.level`、`route.level`、`process.level`、`checkpoint.level`（`L1~L4`）
- **配置版本表**：
```sql
CREATE TABLE config_version (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  target_type VARCHAR(30) NOT NULL,  -- PROCESS/NODE/ROUTE/CHECKPOINT/CONNECTOR...
  target_id BIGINT NOT NULL,
  version INT NOT NULL,
  content JSON,            -- 该版本完整配置快照
  change_note VARCHAR(500),
  operator VARCHAR(50),
  status VARCHAR(20),      -- DRAFT/PENDING_APPROVAL/PUBLISHED/ROLLED_BACK
  created_at DATETIME,
  UNIQUE KEY uk_version (target_type, target_id, version)
);
```
- **连接器 / 采集任务表**：
```sql
CREATE TABLE connector (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  connector_type VARCHAR(20),   -- DB/EXCEL/CMDB/API/LOG/IOT
  name VARCHAR(100), db_type VARCHAR(20),
  host VARCHAR(100), port INT, username VARCHAR(100), encrypted_pwd VARCHAR(255),
  config JSON, enabled TINYINT DEFAULT 1, created_at DATETIME
);
CREATE TABLE import_job (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  connector_id BIGINT, job_type VARCHAR(20),  -- MANUAL/SCHEDULED
  cron VARCHAR(50), status VARCHAR(20),       -- RUNNING/SUCCESS/FAIL
  summary VARCHAR(500), start_time DATETIME, end_time DATETIME
);
CREATE TABLE import_log (
  id BIGINT PRIMARY KEY AUTO_INCREMENT, job_id BIGINT,
  level VARCHAR(10), message VARCHAR(500), created_at DATETIME
);
```
- 其余沿用 v0.3/v0.4：`node` / `relation` / `process` / `route`+`route_node` / `checkpoint`+`check_result` / `instance`+`instance_node`（带 `biz_no`）。
- **告警 + 工单（v0.6，干预三动作）**：
```sql
CREATE TABLE alert (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  alert_type VARCHAR(30),      -- STUCK/FAIL/TIMEOUT/CHECK_FAIL...
  target_type VARCHAR(20), target_id BIGINT,   -- 站点/实例/路线
  message VARCHAR(500), severity VARCHAR(10),
  disposition VARCHAR(50),     -- NOTIFY/TICKET/AUTO_ACTION（可组合）
  status VARCHAR(20) DEFAULT 'OPEN',           -- OPEN/RESOLVED
  created_at DATETIME, resolved_at DATETIME
);

CREATE TABLE ticket (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  alert_id BIGINT NOT NULL,
  assignee VARCHAR(50), priority VARCHAR(10),
  status VARCHAR(20) DEFAULT 'OPEN',   -- OPEN/PROCESSING/RESOLVED
  description VARCHAR(500), created_at DATETIME, resolved_at DATETIME
);
```
- **命名与别名体系（v0.7）**：`instance` 表加 `biz_name`（业务别名）+ 通用别名表：
```sql
CREATE TABLE alias (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,
  target_type VARCHAR(30) NOT NULL,  -- PROCESS/ROUTE/INSTANCE/NODE/VIEW/CHECKPOINT
  target_id BIGINT NOT NULL,
  name VARCHAR(100) NOT NULL,
  is_primary TINYINT DEFAULT 0,      -- 是否主显示名
  created_at DATETIME
);
```

| 项 | 内容 |
| --- | --- |
| 日期 | 2026-08-16 |
| 版本 | v1.0（已评审通过） |
| 阶段 | M1（后端建模 + 数据接入） |
| 状态 | ✅ 用户已确认（方案二：独立数据池模块） |

## 1. 背景与目标

平台后端已具备双数据库模式（H2 离线本地 / MySQL 部署，见 M0）。本轮将数据连接能力升级为**独立的数据池模块**：

- 平台可注册管理**多个外部数据库连接**（数据池），类型可插拔：MySQL 8、PostgreSQL、H2（后续 Oracle 等，仅需新增方言适配器 + 驱动）。
- 管理员在**前端可视化**新增 / 编辑 / 测试连通 / 切换「当前连接」/ 浏览库表与数据预览。
- **平台自身存储库保持独立**（H2 离线 / MySQL 部署，不受数据池影响）。
- 设计上**预留分布式拓展**：连接配置存平台库（全局共享），各节点从同一份配置各自建连接池（无状态），「当前连接」是全局配置字段、切换即时全局生效。

### 1.1 明确不做（YAGNI）
- 平台自身存储库的运行时切换（已在上轮决策排除）。
- 数据池的实际采集 / 监控 / 特征推断使用（属 M2 监控排查，本模块只做「连接 + 管理 + 浏览」，为 M2 铺路）。
- 连接配置变更的实时广播/消息机制（远期，文档留扩展点）。

## 2. 范围（M1）

| 包含 | 说明 |
| --- | --- |

## 3. 架构（后端新增 `datasource` 包）

```
com.datalink.platform.datasource/
├── entity/Connector            # 复用 connector 表，V3 迁移扩展字段
├── dto/                        # ConnectorVO（不回显密码）/ SaveConnectorRequest / TestResult / TableInfo / PreviewResult
├── mapper/ConnectorMapper      # MyBatis-Plus BaseMapper + 唯一激活等自定义 SQL
├── service/ConnectorService    # CRUD / 测试 / 激活 / 浏览，密码 AES 加解密，事务
├── controller/ConnectorController
├── dialect/                    # ★ 可插拔方言层
│   ├── DbDialect              # 接口：driverClass / buildJdbcUrl / testSql / quote(标识符) / previewSql / 是否需 SSL 参数
│   ├── MySqlDialect / PostgreSqlDialect / H2Dialect
│   └── DbDialectFactory       # 按 db_type 分派，未支持类型抛 BusinessException
├── pool/ConnectionPoolRegistry # HikariCP 连接池注册表（懒加载/失效重建/关闭回收/按连接器 id 缓存）
└── util/AesUtil                # AES-GCM 加解密（密钥来自配置 datalink.crypto.key）
```

### 3.1 方言可插拔（核心扩展点）
- `DbDialect` 接口定义每种数据库的差异点：驱动类、JDBC URL 拼装、测试 SQL、标识符引用符、预览 SQL。
- `DbDialectFactory` 按 `connector.db_type` 返回对应实现；新增数据库类型 = 新增一个 Dialect 实现 + 加 JDBC 驱动依赖，**业务代码零改动**。
- 已支持：`MYSQL` → MySqlDialect、`POSTGRESQL` → PostgreSqlDialect、`H2` → H2Dialect。
- 预留枚举：`ORACLE` 等在 `ConnectorDbType` 枚举中列出但 M1 不实现（前端下拉不出现，防止配置了无法使用）。

### 3.2 连接池管理
- `ConnectionPoolRegistry`：以连接器 id 为键缓存 HikariCP `DataSource`，**首次使用时懒加载**（测试连通用独立短连接，不占池）。
- 连接参数修改后**失效并重建**连接池；删除连接器时**关闭并移除**连接池；应用关闭时释放全部。
- 浏览库表/数据预览走对应连接器的连接池（只读，`connection.setReadOnly(true)`）。

## 4. 数据模型（V3 迁移）

`V3__connector_expand.sql` 放在 `db/migration/common/`（H2 与 MySQL 通用，兼容 M0 既有 `connector` 表）：

`connector` 表新增列：
| 列 | 类型 | 说明 |
| --- | --- | --- |
| database_name | VARCHAR(100) | 连接的实际库名（必填，与显示名 name 无关） |
| schema_name | VARCHAR(100) | 模式名（可选，默认库名） |
| is_active | TINYINT DEFAULT 0 | 是否当前连接（全局唯一 1 个） |
| last_test_status | VARCHAR(20) | OK / FAIL / 空 |
| last_test_time | DATETIME | 最近测试时间 |

> 复用现有 `connector_type`（固定 `DB`）、`db_type`、`host`、`port`、`username`、`encrypted_pwd`（AES）、`config`（JSON，存额外参数）、`enabled`。

唯一激活约束：应用层保证 `is_active=1` 仅一条（激活时事务内先全部置 0 再置目标 1）。因跨库一致性，不在 DB 层做部分唯一索引。

## 5. REST 接口（统一 `/api` 前缀）

| 方法 | 路径 | 说明 | 返回 |
| --- | --- | --- | --- |
| GET | `/api/connectors` | 分页 + 关键字（name/host/db） | `PageResult<ConnectorVO>` |
| GET | `/api/connectors/{id}` | 详情（不含密码） | `ConnectorVO` |
| POST | `/api/connectors` | 新建（密码必填，AES 加密入库） | `ConnectorVO` |
| PUT | `/api/connectors/{id}` | 修改（密码留空=不修改） | `ConnectorVO` |
| DELETE | `/api/connectors/{id}` | 删除（关闭连接池） | `Result<Void>` |
| POST | `/api/connectors/{id}/test` | 测试连通 | `TestResult{ok, latencyMs, dbVersion, message}` |
| POST | `/api/connectors/{id}/activate` | 设为当前（自动取消其它） | `Result<Void>` |
| GET | `/api/connectors/{id}/tables` | 库表清单（schema 限定） | `List<TableInfo{name, type, remark?}>` |
| GET | `/api/connectors/{id}/tables/{table}/preview` | 数据预览（默认 50 行，`LIMIT ?` 方言适配） | `PreviewResult{columns[], rows[], rowCount}` |

安全约束：
- `ConnectorVO` **永不包含密码**；`SaveConnectorRequest` 的密码在编辑时可选。
- 密码 AES-256-GCM 加密（`encrypted_pwd`），密钥来自 `datalink.crypto.key`（≥32 字节，环境变量 `DATALINK_CRYPTO_KEY` 覆盖），不回显、不写日志。
- 所有「浏览」均为只读连接；数据预览限制行数，防大表拖垮。

## 6. 前端（改造「数据接入」页 `DataSourceView.vue`）

- **连接列表**（真实数据）：名称 / 类型徽标（MySQL/PG/H2）/ 主机:端口 / 库名 / 当前连接标记 / 最近测试状态与时间。
- **新增 / 编辑表单**：名称、类型（下拉 MYSQL/POSTGRESQL/H2）、主机、端口、库名、用户名、密码（编辑时留空=不改）、备注。
- **行操作**：测试连接（绿/红 + 延迟）、设为当前（确认后唯一）、编辑、删除（确认）、浏览（展开该连接的库表清单 → 点表 → 数据预览表格）。
- 「当前连接」用醒目徽标；连接失败/未测试有状态标识。
- 前端 `src/api/index.ts` 新增 `fetchConnectors` 等真实接口，替换 mock（`mockData` 中 connectors 保留为回退）。

## 7. 分布式拓展预留（现在不实现，只留扩展点）

- 连接配置存平台库 → 多节点共享同一份配置，天然一致。
- 每节点各自维护 `ConnectionPoolRegistry`（无状态、本地缓存），「当前连接」是配置字段，切换后各节点下次读取即生效。
- 预留扩展点（文档标注，不实现）：
  - 配置变更广播 / 刷新机制（如 `@EventListener` + 定时刷新或消息中间件，M 级集群时引入）。
  - 连接池大小、闲置回收等参数集中配置。
- NFR：数据池面向**几十到几百个连接**量级；单连接测试/浏览 p95 < 2s。

## 8. 安全与合规

- 数据源密码 AES 加密存储、界面不明文回显、日志脱敏（`encrypted_pwd`、密码字段不打日志）。
- 数据池连接按「最小权限」约定（只读账号）在文档中强调。
- 敏感库（财务/支付/L1）访问审计沿用平台操作日志（`operation_log`，M1 起写操作记日志）。
